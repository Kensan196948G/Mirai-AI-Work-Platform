## 3. 総合判定と理由

**判定: 条件付き利用可（Conditional Go）**

- **条件1（必須）**: P1 レート制限・P3 viewer 権限・P2 会話権限チェックの実装（第2段階で実施）
- **条件2（必須）**: 本番 AI は demo 応答のままでは利用不可 → DeepSeek キー登録（要承認）or demo 明示運用の決定
- **条件3（推奨）**: バックアップ・復旧テストの実行証跡取得、負荷テスト実施
- **条件4（推奨）**: ファイル実体配信（P4）の on-prem/R2 方針決定

## 4. 概要・利用者・課題・価値（各15件以上）

### 4.1 概要（15件）
1. Cloudflare Workers + Hono + Neon PostgreSQL + React 19 のサーバーレス構成
2. Chat（DeepSeek/demo AI 応答）
3. Work（Goal→Plan→承認→Task→Artifact→Review の AI 業務実行）
4. Projects（メンバー・Quota・Files・Artifacts 管理）
5. Files（メタデータ管理・チェックサム・Quota 判定）
6. Agents（実行履歴・資源利用表示）
7. Admin（利用者/Project/AI 設定/監査ログ）
8. 認証: PBKDF2-SHA256 + HttpOnly セッション Cookie
9. RBAC: admin / project_owner / user / service_account
10. 監査ログ: 全主要操作を記録（action/resource/result/ip/request_id）
11. ストレージ保護: 70/80/85/90/95% 段階制御・Quota・書込み停止
12. デプロイ: 本番 ai-work.mirai-dx-platform.com / MVP ai-work-mvp.mirai-dx-platform.com
13. 本番は Cloudflare Access 保護（owner-only）
14. OpenDesign 由来のデザインシステム（oklch トークン・レスポンシブ）
15. 空DB Migration→Seed→Verify 再実行可能な運用設計

### 4.2 利用者（15件）
1. 本社 IT・DX 部門（7名）: 管理者・運用者
2. 本社スタッフ: 経理・総務・人事（Chat/Work）
3. 現場技術者: 施工管理・品質管理（Files/Work）
4. 経営層: ダッシュボード・監査ログ閲覧
5. 協力会社: 将来的な外部利用者（現状は社内ユーザーのみ）
6. プロジェクトオーナー: Project 作成・メンバー管理
7. 一般利用者: Chat/Work/Files 個人利用
8. 閲覧者（viewer）: 読み取り専用（現状は書き込み可 → P3 で修正）
9. サービスアカウント: 将来の API 連携用
10. 管理者: 利用者登録・権限変更・AI 設定
11. 監査担当: 監査ログ閲覧
12. 障害対応者: health チェック・ログ確認
13. 新規利用者: 自己登録は不可（管理者登録のみ）
14. モバイル利用者: レスポンシブ対応（375px 確認済み）
15. キーボード操作利用者: Tab 移動対応確認済み

### 4.3 課題（15件）
1. レート制限なし（P1）→ ログイン総当たり・API 乱用リスク
2. viewer が書き込み可能（P3）→ 権限設計の不整合
3. 会話作成時の Project 権限未チェック（P2）
4. ファイル実体の保存・配信なし（P4）→ ダウンロード不可
5. AI エラー詳細がログに残らない（P5）→ 障害追跡困難
6. health の DB エラー詳細応答（P6）→ 情報漏えい
7. セッション掃除なし（P7）→ sessions 肥大化
8. AI system プロンプトなし（P8）→ インジェクション対策不足
9. 本番 AI が demo 応答（キー未登録）
10. 土木建設特化機能なし（工事情報・図面・工程表）
11. 通知機能なし（メール・Slack・Teams）
12. Excel/PDF 生成・連携なし
13. 検索機能なし（会話・ファイル全文検索）
14. バックアップ復旧の実証テストなし
15. 負荷テスト・性能 SLO 未設定

### 4.4 価値（15件）
1. AI チャットで定型業務の時間削減（試算: 1人/日 30分）
2. Work フローで手順化された AI 業務実行
3. 監査ログで全操作の追跡可能性
4. RBAC で部門間アクセス制御
5. Quota・保護モードで容量事故防止
6. クラウド構成で on-prem 不要（但し /mnt/storage は on-prem 要件）
7. OpenDesign 準拠で UI 一貫性
8. 空DBからの再構築可能な運用
9. Cloudflare Access で本番保護
10. 監査ログ・変更履歴で内部統制支援
11. 権限差検証（403）で認可の確認可能
12. ダミーデータでデモ・研修可能
13. CI/CD で品質ゲート
14. セキュリティスキャンで秘密情報混入防止
15. 文書体系が整備され少人数運用可能

### 4.5 強み（15件）
1. 主要業務フロー（Chat/Work/Projects/Files/Agents/Admin）が実動
2. 62件の単体テスト・20/20 スモーク・19/19 E2E

### 4.6 弱み・リスク（15件以上、深刻度分類）

**Critical**
1. C-1: ファイル実体保存・配信なし（P4）→ 成果物ダウンロード不可、業務利用不可

**High**
2. H-1: レート制限未実装（P1）→ 総当たり攻撃
3. H-2: viewer 書き込み可（P3）→ 権限逸脱
4. H-3: 会話作成時の Project 権限未チェック（P2）→ 情報混在
5. H-4: 本番 AI が demo 応答 → 実業務での AI 価値未実現
6. H-5: バックアップ・復旧テスト未実証 → データ喪失時の復旧不能リスク
7. H-6: AI エラー詳細のログ欠如（P5）→ 障害追跡不能
8. H-7: プロンプトインジェクション対策なし（P8）→ AI 経由の情報漏えい

**Medium**
9. M-1: health が DB エラー詳細を応答（P6）
10. M-2: セッション掃除なし（P7）
11. M-3: 負荷テスト未実施・性能 SLO なし
12. M-4: 通知機能なし
13. M-5: 全文検索なし
14. M-6: フロントエンド単体テストなし
15. M-7: 土木建設特化機能なし

**Low**
16. L-1: ページング限界（files 50件/audit 500件）
17. L-2: モバイル PWA 未対応
18. L-3: 多要素認証（Entra ID/HENNGE 連携）未対応
19. L-4: 依存ライブラリのライセンス表記（LICENSE ファイルなし）

# Mirai AI ワークプラットフォーム 導入開始ガイド

**文書状態：設計段階**

## 1. 目的

本書は、Pilot環境の導入を開始する際の確認事項と推奨順序を示す。記載コマンドや設定値は設計案であり、対象機器、Linuxディストリビューション、サービス構成を確認してから確定する。

## 2. 導入前提

- Pilot利用者は約10名とする。
- Linuxホスト、アプリケーション実行環境、データベース、DeepSeek API接続を準備する。
- 新規10TB外付けHDDを1台使用する。
- HDDはGPT、ext4で構成し、UUID指定で `/mnt/storage` へ直接マウントする。
- mergerfs、既存4TB HDDと新規4TB HDDの統合構成は使用しない。
- 重要データは10TB HDDとは別の媒体または別システムへバックアップする。

## 3. 事前準備チェック

- [ ] 企画書、要件定義書、詳細設計書が承認対象として提示されている。
- [ ] 10TB HDDの型番、シリアル番号、公称容量、接続方式を記録した。
- [ ] 対象デバイスを誤認しないため、既存ディスク一覧を取得した。
- [ ] HDDの初期診断と取得可能なS.M.A.R.T.情報を確認した。
- [ ] 破壊的なパーティション作成・フォーマットについて人間の承認を得た。
- [ ] バックアップ先と復元試験の責任者を決めた。
- [ ] API秘密情報をソースや文書へ記載しない管理方法を決めた。
- [ ] Pilot利用者、管理者、プロジェクト所有者の候補を確定した。

## 4. 推奨導入順序

1. Linuxホストの更新方針、時刻同期、管理者アクセスを確認する。
2. 10TB HDDを識別し、初期健全性を確認する。
3. GPTパーティションとext4を作成する。
4. ファイルシステムUUIDを記録する。
5. `/mnt/storage` を作成し、所有者と最小権限を設定する。
6. `/etc/fstab` にUUID指定を登録し、自動マウントを確認する。
7. 再起動後も期待するUUIDが同一パスへマウントされることを確認する。
8. アプリケーション専用ユーザー、データベース、秘密情報を準備する。
9. アプリケーションサービスに `/mnt/storage` のマウント依存を設定する。
10. 未マウント、読取り専用、I/O異常時に書込みを停止する検査を組み込む。
11. 初期利用者、役割、プロジェクト、容量上限を登録する。
12. 監視、バックアップ、監査、障害手順を有効化して受入試験を行う。

## 5. ストレージの初期ディレクトリ案

```text
/mnt/storage/
├── users/
├── projects/
├── artifacts/
├── knowledge/
├── processing/
├── temp/
└── backups-staging/
```

`lost+found` はアプリケーションの走査対象外とする。`backups-staging` は別系統へ転送する一時領域であり、同じHDD上に残すだけではバックアップにならない。

## 6. 初期設定候補

| 項目 | 初期候補 | 確定方法 |
|---|---:|---|
| 利用者容量上限 | 100GB／人 | Pilot利用実績と全体予備容量で見直す |
| プロジェクト容量上限 | 50、100、500GBなど | 所有者申請と管理者承認で設定 |
| 運用予備 | 実使用可能容量の10%以上 | フォーマット後の実測値から算出 |
| 一時データ保持 | 24時間～7日 | 処理要件と再実行可能性で確定 |
| 同時エージェント数 | ホスト性能に応じた上限 | 負荷試験で確定 |

## 7. 初回受入確認

- ログインと役割による表示・操作制御
- 利用者領域とプロジェクト領域の分離
- ファイルのアップロード、取得、移動、削除
- Chatの会話保存とプロジェクト文脈選択
- Workの計画、実行、成果物、確認、再実行
- エージェントが許可領域以外へアクセスできないこと
- 容量上限超過と全体使用率しきい値の制御
- HDD切断・未マウント・読取り専用時の書込み停止
- 再起動後のUUIDマウント
- 別系統バックアップからの復元
- 管理操作と主要データ操作の監査記録

## 8. 導入中止条件

対象ディスクを一意に識別できない、バックアップ先が未決定、秘密情報の安全な保存方法がない、ストレージ異常時に書込みを止められない、利用者間分離を検証できない場合はPilot開始を延期する。

## 9. 初回利用者への案内

利用目的、保存可能データ、禁止データ、容量上限、AI回答の確認責任、成果物の取扱い、障害連絡先を説明する。AI生成物は正確性・権利・機密性を人が確認してから業務利用する。

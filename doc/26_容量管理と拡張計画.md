# 容量管理と拡張計画

**文書状態：設計段階**

## 1. 基本方針

初期ストレージは新規10TB外付けHDD 1台とする。メーカー公称10TBは約9.1TiBであり、ext4の管理領域・予約領域を差し引いた構築後の実測値を容量管理の基準とする。UUID指定で`/mnt/storage`へ直接マウントし、既存4TB HDDや新規4TB HDDとの統合、mergerfsは採用しない。

## 2. 容量配分

- ファイルシステム全体の10%以上を運用予備として確保する。
- PilotのUser Quotaは100GB/Userを初期候補とする。
- Project Quotaは50GB、100GB、500GB等から管理者が設定する。
- User QuotaとProject Quotaの重複計上・優先関係は**未決**であり、実装前に一意に定義する。
- 全体保護制限は個別Quotaより常に優先する。

## 3. 監視指標

日次または監視システムで、実使用可能容量、使用量、空き容量、使用率、日次・月次増加量、最大ユーザー、最大Project、Temp量、バックアップ量、マウント状態、I/Oエラーを記録する。取得可能な場合はS.M.A.R.T.情報と温度も監視する。

## 4. しきい値と動作

| 使用率 | 動作 |
|---:|---|
| 70% | 注意通知。増加要因と不要データを確認する |
| 80% | 拡張・移行計画を開始し、必要容量と期限を確定する |
| 85% | 管理者警告。新規大容量案件の受入可否を審査する |
| 90% | 大容量JobとUploadを制限する |
| 95% | 緊急保護モード。重要処理以外の書込みを停止する |

## 5. 予測方法

直近30日・90日の増加量から、80%、90%、95%へ到達する予測日を算出する。大型Project開始、データ移行、バックアップ一時領域などの予定負荷を加算し、季節変動や一時的なTemp増加を分けて評価する。

## 6. 拡張候補

| 候補 | 評価観点 |
|---|---|
| より大容量の単一媒体へ移行 | 作業停止時間、再移行頻度、単一障害点 |
| 冗長ストレージへ移行 | 可用性、導入費、運用難度。ただし冗長化はバックアップの代替ではない |
| 追加ストレージへ用途分離 | データ配置規則、Quota、監視、復元手順の複雑化 |
| 別システム・オブジェクトストレージ | 帯域、費用、暗号化、権限、データ所在 |

採用方式、調達時期、停止許容時間はPilot実測後に決定するため**未決**である。

## 7. 拡張受入条件

移行前後のファイル件数、総バイト数、チェックサムが一致し、Quota、権限分離、再起動後マウント、未マウント時停止、バックアップ復元が確認できることを必須とする。

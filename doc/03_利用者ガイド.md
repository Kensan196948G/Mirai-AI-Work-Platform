# Mirai AI ワークプラットフォーム 利用者ガイド

**文書状態：設計段階**

## 1. 対象

本書はPilot利用者およびプロジェクト所有者向けの利用案である。画面名称と操作は設計段階であり、実装・受入試験の結果に応じて更新する。

## 2. 基本概念

| 機能 | 用途 |
|---|---|
| Chat | AIとの対話、添付ファイルを用いた質問、会話履歴の参照 |
| Work | 目標から計画と作業を進め、成果物を確認・再実行する |
| Projects | 共同作業のメンバー、ファイル、知識、成果物をまとめる |
| Files | 個人またはプロジェクトのファイルを管理する |
| Agents | AIエージェントの実行状態、履歴、エラーを確認する |
| Artifacts | AIや業務処理が生成した成果物を管理する |

## 3. 利用開始

1. 管理者から利用者ID、初期案内、利用規約を受け取る。
2. 指定URLへアクセスし、認証する。
3. 表示名、所属、通知設定など許可された項目を確認する。
4. 自分の作業領域と参加プロジェクトを確認する。
5. 容量上限、利用可能なAI、ファイル制限を確認する。

## 4. Chatの利用

1. 新しい会話を作成する。
2. 必要に応じてプロジェクト文脈を選ぶ。
3. 質問または依頼を具体的に入力する。
4. 必要なファイルだけを添付する。
5. 回答の根拠、数値、対象範囲を人が確認する。
6. 継続利用する会話には判別しやすい題名を付ける。

機密情報、個人情報、契約上外部提供できない情報は、許可方針を確認せずに入力しない。AI回答は事実や社内決定を自動的に保証しない。

## 5. Workの利用

1. 達成したいGoalを入力する。
2. 生成されたPlanの範囲、入力、成果物、危険な操作を確認する。
3. 必要に応じて計画を修正または承認する。
4. Taskの進捗と道具の実行結果を確認する。
5. Artifactを開き、内容・形式・保存先を確認する。
6. 不十分な場合は理由を添えて再実行する。
7. 完了時に採用・不採用と判断根拠を記録する。

削除、外部送信、公開、権限変更など元に戻しにくい操作は、エージェントへ全面委任せず人が最終確認する。

## 6. Projectsの利用

プロジェクト所有者は、目的が分かる名称と説明を設定し、必要なメンバーだけを追加する。役割は最小権限とし、メンバー離任時は速やかに削除する。プロジェクトの容量上限を超えそうな場合は、不要データを整理し、管理者へ根拠を添えて増量を申請する。

## 7. Filesの利用

- 保存先が個人領域かプロジェクト領域かを確認する。
- ファイル名に機密情報や個人情報を不用意に含めない。
- アップロード後にサイズ、種別、所有先、更新日時を確認する。
- 同名上書きや削除の挙動を確認し、重要ファイルは履歴または別系統で保護する。
- 一時ファイルや不要な中間成果物は保持方針に従って整理する。
- 容量表示は公称10TBではなく、実測した利用可能容量を基準とする。

## 8. 成果物の確認

HTML、Markdown、PDF、Office文書などが成果物候補となる。利用者は、内容の正確性、文字化け、リンク、レイアウト、アクセシビリティ、権利、機密性、提出先の要件を確認する。生成履歴と元のWorkを追跡できる状態で保存する。

## 9. エラー時の対応

| 表示・症状 | 利用者の対応 |
|---|---|
| 容量上限超過 | 不要データを整理するか、所有者・管理者へ相談する |
| ストレージ保護中 | 再試行を繰り返さず管理者通知を確認する |
| AI接続失敗 | 入力を保持し、時間を置いて再試行する |
| エージェント失敗 | エラー、実行ID、時刻、直前操作を記録する |
| 権限不足 | 保存先と参加プロジェクトを確認し、必要時のみ申請する |
| 不審なアクセス | 操作を中止して管理者へ報告する |

## 10. 安全な利用の原則

- 必要なデータだけを入力する。
- AIの出力を人が検証する。
- 他者の領域へアクセスしようとしない。
- APIキー、パスワード、秘密鍵をChatやファイルへ保存しない。
- 障害時にローカルの代替パスへ勝手に保存しない。
- 問題報告には時刻、画面、実行ID、再現手順を含める。

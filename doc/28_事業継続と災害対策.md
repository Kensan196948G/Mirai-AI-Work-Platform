# 事業継続と災害対策

**文書状態：設計段階**

## 1. 目的

Mirai AI ワークプラットフォームの停止やデータ損失が発生した場合に、人命・安全、情報保護、重要業務の順で対応し、復旧判断と連絡を統制する。

## 2. 想定事象

- 新規10TB外付けHDDの故障、切断、read-only化、I/Oエラー
- Linuxホスト、USB筐体、電源、ネットワークの障害
- 誤削除、権限設定ミス、マルウェア、認証情報漏えい
- 火災、水害、地震、盗難など同一拠点を失う事象
- DeepSeek APIその他外部サービスの停止

## 3. 継続方針

| 状態 | 基本対応 |
|---|---|
| ストレージ未マウント・異常 | Upload、Artifact生成など新規書込みを停止。OSルートへの誤書込みを防ぐ |
| AI API停止 | AI実行を停止または待機し、既存成果物の参照可否を案内する |
| セキュリティ事故疑い | 対象アカウント・経路を隔離し、証跡を保全する |
| 拠点災害 | 人員安全を優先し、別系統バックアップの健全性を確認する |

## 4. 体制

インシデント責任者、技術復旧担当、情報セキュリティ担当、業務連絡担当、経営判断者を事前指定する。氏名、連絡網、代行者、社外連絡条件は**未決**である。

## 5. 復旧優先順位

1. 認証・権限と監査機能
2. データベースおよびシステム設定
3. 重要ProjectとUser Workspace
4. Artifacts、Knowledge、一般Project
5. 再生成可能なTemp、Cache、Processingデータ

## 6. RPO・RTO

本番RPO、RTO、重要業務区分は**未決**である。Pilotでバックアップ時間、実測復元時間、許容可能なデータ損失、利用部門の業務影響を測定し、正式運用前に承認する。

## 7. 災害対策

- バックアップは10TB HDDと同一障害で失われない別媒体または別システムに保存する。
- 別拠点保管、暗号化、鍵の保管、オフラインまたはイミュータブル保護の要否を評価する。
- 電源保護、物理固定、温湿度、ケーブル抜け、盗難対策を確認する。
- 年1回以上を候補として復旧訓練を行う。正式頻度は**未決**である。

## 8. 復旧完了条件

データ整合性、権限分離、代表業務、監査ログ、バックアップ再開を確認し、責任者が残存リスクと欠損を承認した時点で復旧完了とする。

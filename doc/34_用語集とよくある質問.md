# 用語集とよくある質問

**文書状態：設計段階**

## 1. 用語集

| 用語 | 説明 |
|---|---|
| Pilot | 約10名、3～6か月を目安に実利用と課題を測る初期運用 |
| Workspace | ユーザー単位の作業・ファイル領域 |
| Project | 複数メンバーが共有する業務単位と保存領域 |
| Artifact | AIまたはユーザーの作業で生成された成果物 |
| Agent | GoalからPlanを作り、許可されたToolで処理を実行する機能 |
| Sandbox | Agentのファイル・ネットワーク・資源アクセスを隔離する実行環境 |
| Quota | UserまたはProjectが利用できる容量上限 |
| ext4 | 新規10TB HDDに採用するLinux向けファイルシステム |
| UUID | デバイス名が変わっても対象HDDを識別する一意識別子 |
| `/mnt/storage` | アプリケーションが利用する10TB HDDの固定マウント先 |
| TiB | 2の累乗基準の容量単位。公称10TBは概ね約9.1TiBと表示される |
| RPO | 障害時にどの時点までデータを戻せればよいかを示す目標 |
| RTO | 障害発生から業務復旧までの目標時間 |
| S.M.A.R.T. | HDDの健全性情報。USB接続方式によって取得できない場合がある |

## 2. よくある質問

### Q. 10TBなのに約9.1TiBと表示されるのは異常ですか。

異常ではない。メーカー公称の10進単位とOS表示の2進単位の違いが主因で、ext4の管理・予約領域により実使用可能容量はさらに小さくなる。構築後の実測値を管理基準とする。

### Q. 既存4TB HDDと新規10TB HDDを合わせて14TBとして使いますか。

使わない。初期運用は新規10TB HDD 1台のみで、既存4TB HDDは統合しない。

### Q. 既存4TB HDDのデータはどうしますか。

移行対象がある場合だけ条件付き移行を行う。件数、総バイト数、チェックサム、受入試験が完了するまで元HDDを消去しない。

### Q. 10TB HDDだけでバックアップになりますか。

ならない。同じHDD内の複製では物理故障に耐えられないため、別媒体または別システムへ保存し、復元試験を行う。

### Q. HDDが外れた場合はどうなりますか。

未マウントを検知して新規UploadやArtifact生成を停止し、OSルートファイルシステムへの誤書込みを防ぐ設計とする。

### Q. 容量を使い切るまで利用できますか。

できない。10%以上を運用予備として確保し、使用率90%で大容量処理を制限、95%で緊急保護する。

### Q. SSOやOneDriveは利用できますか。

Entra ID SSO、OneDrive、SharePointは現時点で保留・初期スコープ外である。

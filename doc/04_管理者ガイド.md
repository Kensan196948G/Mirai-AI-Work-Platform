# Mirai AI ワークプラットフォーム 管理者ガイド

**文書状態：設計段階**

## 1. 目的と対象

本書はIT・DX管理者がPilot環境を管理するための設計上の責務、確認項目、判断基準を示す。具体的なコマンド、サービス名、連絡先は実装・運用設計で確定する。

## 2. 管理者の責務

- 利用者、役割、プロジェクト、容量上限を管理する。
- AI提供者、モデル、利用制限、秘密情報を管理する。
- ストレージ使用量、マウント状態、I/O異常を監視する。
- エージェント実行、失敗、資源利用を監視する。
- 監査ログを検索し、異常操作を調査する。
- バックアップの成功と復元可能性を確認する。
- 障害、セキュリティ事象、容量逼迫を利用者へ通知する。

## 3. 日次確認

- [ ] `/mnt/storage` が期待するUUIDで読書き可能にマウントされている。
- [ ] ファイルシステム使用率と空き容量が基準内である。
- [ ] I/Oエラー、読取り専用化、切断記録がない。
- [ ] アプリケーション、データベース、エージェントサービスが正常である。
- [ ] 失敗したWork、長時間実行、異常なAPI利用がない。
- [ ] バックアップジョブの結果と転送先を確認した。
- [ ] 重大な認証失敗、権限拒否、管理操作がない。

## 4. 利用者・役割管理

利用開始前に本人、所属、必要機能、所属プロジェクト、容量を確認する。無効化と削除を分け、離任時は先に認証とアクセスを停止し、データ移管と保持要否を決める。管理者権限は日常利用アカウントと分け、付与理由と承認者を監査可能にする。

## 5. プロジェクト管理

プロジェクト作成時に目的、所有者、メンバー、機密区分、予定期間、容量上限を登録する。所有者不在、期限超過、過剰権限、長期未利用を定期点検する。削除は即時物理削除とせず、保持期間、復元可能性、監査記録を確認して実施する設計とする。

## 6. ストレージ管理

| 状態 | 管理方針 |
|---|---|
| 70% | 注意通知、増加傾向の確認 |
| 80% | 拡張・移行計画を開始 |
| 85% | 管理者警告、上位利用者・プロジェクトを精査 |
| 90% | 大容量アップロード・ジョブを制限 |
| 95% | 緊急保護モード、新規大容量書込みを停止 |
| 未マウント・読取り専用・I/O異常 | 書込み停止、利用者通知、障害手順へ移行 |

公称10TBは約9.1TiBであり、ext4の管理領域等を除いた実測値を管理基準とする。ファイルシステム全体の10%以上を運用予備として確保し、個別容量上限より全体保護を優先する。mergerfsは使用しない。

## 7. バックアップ管理

10TB HDDは単一障害点である。重要プロジェクト、設定、データベース、監査情報を別媒体または別システムへ保存する。バックアップ対象、頻度、保持世代、暗号化、転送、失敗時通知、RPO、RTOをPilot開始前に承認する。定期的に別環境または隔離領域へ復元し、件数、容量、チェックサム、アプリケーション参照を確認する。

## 8. AI・エージェント管理

- APIキーをSecretとして管理し、画面・ログ・DBへ平文表示しない。
- 利用可能モデル、実行時間、CPU、メモリ、出力容量、同時実行数を制限する。
- File、Shell、Network等の道具をプロファイル化し、必要な実行だけ許可する。
- 他利用者・他プロジェクト領域をコンテナへマウントしない。
- 異常なトークン消費、繰返し失敗、危険操作要求を監視する。

## 9. 監査と調査

ログイン、ファイル操作、エージェント実行、管理操作、設定変更、権限変更、容量変更を検索可能にする。調査時は時刻、利用者、要求ID、実行ID、対象、結果、接続元を相関する。監査ログ自身の変更・削除権限を制限する。

## 10. 障害時の優先順位

1. 新規書込みを安全に停止する。
2. 影響範囲とデータ整合性を確認する。
3. 利用者へ事実、影響、回避策を通知する。
4. 10TB HDDの再接続やファイルシステム修復は手順と承認に従う。
5. 必要時は別系統バックアップから復元する。
6. 原因、対応、復旧確認、再発防止を記録する。

## 11. 変更管理

設定変更は目的、影響、実施者、確認者、戻し方を記録する。ストレージ初期化、権限一括変更、データ削除、秘密情報変更、外部公開、本番反映は人の承認境界とする。変更後は機能、セキュリティ、監査、バックアップを再確認する。

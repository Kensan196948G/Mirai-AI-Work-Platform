# Mirai AI ワークプラットフォーム 利用体験とアクセシビリティ

**文書状態：設計段階**

## 1. 目的

本書は、利用者が安全かつ迷わず作業できる体験と、障害の有無や入力手段によらず主要機能へ到達できるための設計基準を示す。目標はJIS X 8341-3およびWCAG 2.2のレベルAA相当を候補とし、適合表明の有無と対象範囲は試験後に確定する。

## 2. 利用体験の原則

- Chat、Work、Project、個人領域の違いを常に明確にする。
- AIが行うこと、人が確認すること、システムが禁止することを区別する。
- 実行状態と保存状態を隠さない。
- 失敗時に入力を失わせず、次の行動を示す。
- 専門用語を減らし、必要な場所で説明する。
- 危険な操作は速度より理解と確認を優先する。
- 容量とAI利用量を、利用者が自分で予測できる形で示す。

## 3. 主要利用シナリオ

| シナリオ | 完了条件 |
|---|---|
| 初回利用 | ログインし、保存先と禁止事項を理解してChatを開始できる |
| 資料への質問 | 正しいProjectと添付ファイルを選び、回答を確認できる |
| 業務実行 | Goal、Plan、進捗、成果物、確認状態を追跡できる |
| 共同作業 | Projectのメンバーと権限を理解してファイルを共有できる |
| 障害対応 | 書込み不可の理由と、自分が行うべき対応を判断できる |
| 管理対応 | 優先度の高い警告から影響対象と対応手順へ到達できる |

## 4. キーボード操作

- すべての主要操作をキーボードだけで行えるようにする。
- フォーカス位置を視認できるようにする。
- フォーカス順序を視覚的な順序と一致させる。
- モーダル表示中はフォーカスを内部へ保ち、閉じた後は起点へ戻す。
- 「本文へ移動」等のスキップリンクを用意する。
- 単一キーのショートカットは誤操作を防げる設定を持たせる。

## 5. 構造と読み上げ

- 画面ごとに一意で具体的なページタイトルと主見出しを設ける。
- 見出し階層、ランドマーク、リスト、表を意味に沿って使用する。
- 入力欄には可視ラベルと説明を関連付ける。
- ボタン名は「実行」「削除」だけでなく対象や結果が分かる語にする。
- 状態変更、エラー、進捗を適切なライブ領域で通知する。
- アイコンだけの操作にはアクセシブルな名称を付ける。

## 6. 色・文字・表示

- 通常文字と背景は4.5対1以上、大きな文字は3対1以上のコントラストを目標とする。
- 色だけで正常、警告、失敗、選択状態を伝えない。
- 200%拡大で情報や操作が失われないことを確認する。
- 文字間隔を利用者が変更しても重なりや欠落が起きないようにする。
- 動きや点滅を抑え、必要なアニメーションは停止可能にする。

## 7. フォームとエラー

入力前に必須項目、形式、上限を説明する。エラーは入力欄の近くと画面上部の要約に表示し、問題と修正方法を文字で示す。入力済み内容は可能な限り保持する。容量、ファイル種別、権限、AI接続、ストレージ障害を同じ「失敗」にまとめない。

## 8. AI特有の体験

- AI出力であること、使用モデル、生成時刻を確認可能にする。
- 推測と確認済み情報の区別を促す。
- PlanやTool実行の範囲を開始前に確認可能にする。
- 長時間処理は進捗、経過時間、中止方法を示す。
- 再実行によって異なる結果になる可能性を説明する。
- 成果物には生成元のWorkと入力資料への追跡手段を持たせる。
- 危険な操作をAIの文章だけで承認させず、構造化した確認画面を使う。

## 9. 容量・障害時の体験

利用者自身とProjectの使用量、上限、残量、警告段階を表示する。ストレージ保護時は、単なる技術エラーではなく、保存できない操作、参照できる範囲、入力保持の状況、管理者連絡の要否を案内する。再試行を繰り返して状況を悪化させない設計とする。

## 10. 利用者試験

Pilot開始前後に、初回利用者、日常利用者、管理者を対象として主要シナリオを観察する。完了率、所要時間、誤操作、支援要求、理解度、満足度を記録し、改善に反映する。可能な範囲でキーボード利用者、画面読上げ利用者、低視力者の観点を含める。

## 11. 検証方法

- 自動検査によるラベル、コントラスト、構造の一次確認
- キーボードだけでの全主要フロー確認
- 画面読上げによる名前・役割・状態の確認
- 200%および400%拡大、狭い表示幅での確認
- エラー、長時間処理、ストレージ保護状態の確認
- 静的画面だけでなく、フォーカス移動と動的更新の確認

適合状況は「対応済み」「一部対応」「未対応」「対象外」を根拠付きで記録し、実装前の項目を対応済みとしない。

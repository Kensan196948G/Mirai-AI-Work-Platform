# プライバシーとデータガバナンス

**文書状態：設計段階**  
**対象：Mirai AI ワークプラットフォーム Pilot**

## 1. 目的

本書は、会話、アップロード、成果物、Project、Knowledge、利用ログ等の取扱いを統制し、目的外利用、過剰収集、外部AIへの不適切な送信、削除漏れを防ぐための方針を定める。

## 2. データ分類

| 区分 | 例 | 取扱い |
|---|---|---|
| 公開 | 公開済み資料 | 通常管理。公開可否を利用者が勝手に変更しない |
| 社内 | 一般的な業務資料、Project情報 | 認証必須、所属単位でアクセス制御 |
| 機密 | 契約前情報、個人情報、非公開設計 | 必要最小限、外部送信条件を厳格化、監査対象 |
| 秘密 | API Key、パスワード、署名鍵 | 業務データとして保存・LLM送信禁止、Secret管理 |

実際の分類基準、個人情報の範囲、例外承認者はPilot開始前に組織ルールと照合する。

## 3. データライフサイクル

1. **収集**：利用目的に必要な情報だけを取得する。
2. **保存**：所有者、Project、分類、作成日時、保持条件をメタデータで追跡する。
3. **利用**：認可された目的・主体・Toolに限定する。
4. **共有・外部送信**：宛先、目的、最小化、契約条件を確認する。
5. **保管・バックアップ**：原本と別系統バックアップの双方に保護を適用する。
6. **削除**：本体、索引、派生成果物、Temp、期限到来バックアップを対象範囲に含める。

## 4. 保持と削除

- User/Project本体データは現行要件上「明示削除まで保持」だが、正式運用前にデータ区分ごとの上限を定める。
- Tempは24時間から7日を候補とし、処理中データを誤削除しない条件を設ける。
- Processingデータは処理完了と検証後に削除する。
- 監査ログはPilot中原則保持とし、正式な保持期間、法務・調査保全を別途決定する。
- 削除要求は対象、承認、実行、結果、バックアップからの期限付き消去を記録する。

## 5. DeepSeek APIへの送信統制

- System Prompt、Project Context、User Requestを分離し、必要な文脈だけを送信する。
- Secret、認証情報、対象外Projectの情報をPromptへ含めない。
- 機密・個人情報の送信可否、契約・学習利用・保存地域等を導入前に確認する。
- 送信したモデル、日時、利用量、対象Project、結果を追跡可能にする。ただしPrompt本文を監査へ複製する場合はアクセスと保持を制限する。
- 外部Providerの仕様変更時は再評価する。

## 6. 保存場所とバックアップ

新規10TB HDD上の `/mnt/storage` は業務データの主保存領域であり、単一障害点である。未マウント、read-only、I/Oエラー時は書込みを停止し、別パスへ黙って保存しない。重要データは10TB HDDと故障ドメインを分けた別媒体または別システムへ保存する。

バックアップにも原本と同等の分類、暗号化、アクセス制御、保持・削除ルールを適用する。既存4TB HDDを再利用する場合、それだけで10TB全体の完全バックアップとは扱わず、対象範囲・健全性・消去状態を確認する。

## 7. 責任分担

| 役割 | 責任 |
|---|---|
| Data Owner / Project Owner | 利用目的、分類、メンバー、保持・共有判断 |
| Pilot User | 正しい分類、不要データ削除、外部送信ルール順守 |
| IT/DX Admin | アクセス制御、バックアップ、監査、削除運用 |
| Security / Privacy責任者 | 高リスク利用、事故、例外の審査 |

## 8. データ主体・開示等への対応

個人情報を扱う場合、対象データを検索・特定し、開示、訂正、利用停止、削除要求へ組織の規程に沿って対応できるようにする。要求者確認、権利と例外、Project成果物や監査ログとの関係を審査し、実施記録を残す。

## 9. Pilot開始前の決定事項

- 利用可能なデータ分類と禁止データ
- DeepSeek APIへ送信可能な情報とマスキング要件
- データ区分別保持期間、削除SLA、法的保全
- バックアップの保存先、暗号化、保持世代、消去方式
- Privacy Impact Assessmentの要否と問い合わせ窓口

# バックアップ・復元手順

**文書状態：設計段階**

## 1. 目的

新規10TB外付けHDD（公称10TB、約9.1TiB、ext4、`/mnt/storage`）の故障、誤削除、ファイルシステム破損、マルウェア、筐体障害に備え、重要データを別系統へ保全し、復元可能性を確認する。

## 2. 前提と未決事項

- 10TB HDDは単一障害点であり、同一HDD内の複製はバックアップとみなさない。
- バックアップ先は別媒体または別システムとする。
- 本番バックアップ先、頻度、保持世代、暗号化方式、RPO、RTOは**未決**であり、Pilot開始前に承認する。
- 既存4TB HDDは10TB全体を保護できないため、限定データの一時保管に使う場合も正式バックアップとはみなさない。

## 3. 対象

| 優先度 | 対象 | 復元上の注意 |
|---|---|---|
| 最優先 | データベース、認証・権限設定、システム設定 | 相互整合する時点で取得する |
| 高 | Project、User Workspace、Artifacts、Knowledge | 所有者・権限・メタデータも保持する |
| 高 | 監査ログ | 改ざん検知と参照権限を維持する |
| 中 | アプリケーション設定、運用手順 | Secret本体を文書やリポジトリへ保存しない |
| 低 | Temp、Cache、再生成可能なProcessingデータ | 原則対象外とし、必要性を個別判断する |

## 4. バックアップ実施

1. `/mnt/storage`が期待UUIDでマウントされ、read-writeであることを確認する。
2. バックアップ先が10TB HDDとは別系統であり、空き容量と書込み権限を満たすことを確認する。
3. DBは整合性のあるダンプまたはスナップショットを取得する。
4. ファイルデータは増分またはフル方式で取得し、件数、総バイト数、チェックサム、開始・終了時刻を記録する。
5. 暗号化、転送エラー、除外対象、保持期限を確認する。
6. 実行結果を監査可能な場所へ記録し、失敗時は管理者へ通知する。

## 5. 復元手順

1. 障害原因を確認し、障害媒体への書込みを停止する。
2. 復元先の媒体、ext4、マウント先、期待UUID、容量、所有者・権限を確認する。
3. 復元ポイントを選定し、承認者、想定データ損失時間、対象範囲を記録する。
4. DB、設定、ファイルを依存関係に従って復元する。
5. 件数、総バイト数、チェックサム、DB整合性を確認する。
6. ユーザー間・Project間のアクセス分離、代表ファイルの読書き、監査ログ、Agent Sandboxを確認する。
7. 管理者承認後にサービスを再開し、復元結果と欠損を報告する。

## 6. 復元試験

- Pilot開始前および方式変更後に、隔離した検証先へ復元する。
- 少なくともDB、代表Project、代表Workspace、権限、監査ログを確認する。
- 実測復元時間、復元可能時点、エラー、手作業を記録し、未決のRPO/RTO策定材料とする。
- 復元未確認のバックアップは成功扱いにしない。

## 7. 異常時の扱い

バックアップ失敗が継続する場合は、重要データの新規投入を制限し、原因、影響期間、直近の復元可能時点を管理者へ通知する。媒体故障、未マウント、read-only、I/Oエラー時は新規UploadとArtifact生成を停止する。

# 開発環境構築

**文書状態：設計段階**  
**対象：Mirai AI ワークプラットフォーム開発環境**

## 1. 目的

本書は、開発者が本プロジェクトを安全かつ再現可能に扱うための環境構築方針を示す。現時点では技術スタックの全バージョン、実行コマンド、Container定義が確定していないため、実際のリポジトリ構成を確認して具体化する。以下は構築済み・稼働済みを示すものではない。

## 2. 前提

- Linuxを基準実行環境とする。
- ソース管理にGit/GitHubを使用する方針とする。
- アプリケーションはDocker/Container化、設定外部化を前提とする。
- DeepSeek API、DB、セッション署名等のSecretは個人管理ファイルやソースへ保存しない。
- 開発用データは合成データとし、Pilotの実データを複製しない。

## 3. 必要ツールの確認

導入前にREADME、lockfile、Container定義、CI設定を正として、次を確認する。

```text
Git
Container Runtime / Docker Compose相当
プロジェクトが指定する言語RuntimeとPackage Manager
DB Client / Migration Tool
lint / test / buildツール
```

バージョンを推測して導入せず、lockfileやバージョン管理ファイルへ固定する。個人環境とCIで同じ主要バージョンを使う。

## 4. 初期構築手順

1. 正式なリポジトリURLと対象branchを確認してcloneする。
2. リポジトリ内の開発指示、ライセンス、セキュリティ方針を読む。
3. RuntimeとPackage Managerの指定バージョンを用意する。
4. lockfileを変更しない方式で依存関係を導入する。
5. サンプル設定からローカル設定を作成し、実SecretをGit対象外へ配置する。
6. 開発用DBを作成し、承認済みmigrationとseedを適用する。
7. lint、unit test、buildを実行してベースラインを記録する。
8. 開発サービスをloopbackで起動し、healthと主要画面を確認する。

具体的なコマンドは実装確定後に追記し、READMEとCIとの差異をなくす。

## 5. 開発用ストレージ

本番相当の `/mnt/storage` を直接使わない。開発専用ディレクトリまたは専用volumeを使用し、次の論理構成を再現する。

```text
storage/
├── users/{user_uuid}/
├── projects/{project_uuid}/
├── company-knowledge/
├── runtime/
├── cache/
├── archive/
└── system/
```

所有者、path正規化、Quota、read-only、未mount相当の試験を行えるようにする。新規10TB HDDを開発試験で破壊的に操作しない。実機試験が必要な場合は対象の型番、シリアル、UUIDと退避状況を複数人で確認する。

## 6. 環境変数とSecret

| 分類 | 例 | 管理方針 |
|---|---|---|
| 非秘密設定 | port、log level、保存ルート | サンプル値を文書化可能 |
| Secret | API Key、DB password、署名鍵 | Secret機構またはGit対象外ファイル |
| 環境固有ID | 期待するStorage UUID等 | 環境設定に分離し、値をレビュー |

ログや画面へSecretを表示しない。サンプル設定に実値を入れず、必須・任意、形式、既定値を説明する。

## 7. ローカル検証

- 認証済み／未認証、Role違いのテストアカウントを用意する。
- 複数User/Projectでデータ隔離を確認する。
- DeepSeekは通常stubを使用し、実接続は明示した限定試験にする。
- 未mount、read-only、Quota超過を安全な開発volumeで再現する。
- 実装に応じてlint、unit、integration、buildを変更前後で実行する。

## 8. トラブル時

依存関係やDBを無条件に削除・再作成せず、まずバージョン、設定差分、ログ、空き容量、mount状態を確認する。共有環境や10TB HDDに影響する操作は中止し、運用責任者へ確認する。

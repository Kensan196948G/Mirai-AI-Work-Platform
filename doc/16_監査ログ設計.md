# 監査ログ設計

**文書状態：設計段階**  
**対象：Mirai AI ワークプラットフォーム Pilot**

## 1. 目的

本書は、「誰が、いつ、どの対象へ、何を行い、結果がどうだったか」を追跡し、不正利用、誤操作、障害、設定変更を調査できる監査ログの設計を定める。実装・保存先・正式保持期間は未確定である。

## 2. 記録対象

| 分類 | 主なイベント |
|---|---|
| 認証 | ログイン成功・失敗、ログアウト、セッション失効、アカウント停止 |
| 認可 | 重要なアクセス拒否、Role変更、Projectメンバー追加・削除 |
| File | Upload、Download、Move、Delete、復元、チェックサム不一致 |
| Project | 作成、設定変更、Owner変更、Quota変更、削除 |
| Agent | 実行要求、開始、Tool利用、承認、終了、失敗、Artifact生成 |
| Admin | ユーザー管理、システム設定、保持・バックアップ操作 |
| Storage | mount検証、UUID不一致、read-only、I/Oエラー、容量閾値、書込み停止・再開 |
| Security | レート制限、危険ファイル拒否、Path Traversal疑い、Secret検知 |

## 3. イベント項目

| 項目 | 内容 |
|---|---|
| `id` | 一意なイベントID |
| `occurred_at` | UTC基準の発生日時 |
| `request_id` / `trace_id` | API・Jobを横断する相関ID |
| `actor_type` / `actor_id` | User、Service、Systemと主体ID |
| `action` | 安定した命名規則の操作名 |
| `resource_type` / `resource_id` | 対象種別と論理ID |
| `project_id` | 関連Project。該当しなければ空 |
| `result` | success、denied、failed |
| `reason_code` | 判定・失敗理由。機密情報は含めない |
| `source_ip` / `user_agent` | 必要性を確認した接続元情報 |
| `details` | サイズ、変更項目等の最小限メタデータ |

## 4. 記録禁止・マスキング

パスワード、セッション値、API Key、Cookie、Authorizationヘッダー、秘密鍵、ファイル本文、不要なPrompt全文を記録しない。個人情報やファイル名を記録する場合は調査に必要な範囲へ限定し、識別子・ハッシュ等で代替できるか検討する。例外・スタックトレースにもSecretマスキングを適用する。

## 5. 完全性と可用性

- アプリケーションDB上の `audit_logs` と、運用ログの責務を分ける。
- 一般利用者とProject Ownerに監査ログの変更・削除権限を付与しない。
- 追記型保存、アクセス制限、時刻同期、バックアップ、必要に応じた改ざん検知を行う。
- ログ書込み失敗を監視し、重要な管理・権限操作では失敗を見逃さない。
- 10TB HDD障害と同時に監査証跡を失わないよう、重要ログを別系統の保存先へ転送・バックアップする。

## 6. ストレージ障害時の記録

起動時および書込み前の `/mnt/storage` 検証結果を記録する。未接続、未マウント、期待UUID不一致、read-only、I/Oエラーを検知した場合、対象状態、検知元、停止した機能、通知結果を記録する。ただしOSルートの同名ディレクトリへ業務データをフォールバック保存しない。監査基盤も利用不能な場合は、復旧後にOS側の保護された運用記録と突合する手順を準備する。

## 7. 検索とアクセス

IT/DX Adminは期間、actor、action、resource、Project、result、Request IDで検索できるようにする。監査ログ閲覧自体も監査する。大量出力、外部持出し、削除には追加権限と理由を要求する。

## 8. 保持と削除

Pilot中は原則保持する。正式運用前に、ログ分類別の保持期間、オンライン検索期間、アーカイブ、法的保全、期限削除、バックアップからの消去を決定する。容量圧迫時も無断削除せず、保護閾値と承認済み手順に従う。

## 9. 受入観点

- 成功・失敗・拒否イベントが期待項目を伴って記録される。
- UI、API、Agent、Storageの相関をRequest IDで追跡できる。
- Role変更前後の主体・対象・変更点が識別できる。
- Secretやファイル本文がログへ出力されない。
- 時刻ずれ、ログ書込み失敗、保存先停止が検知される。
- バックアップした監査ログを復元・検索できる。

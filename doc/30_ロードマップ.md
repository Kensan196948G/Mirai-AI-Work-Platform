# 導入ロードマップ

**文書状態：設計段階**

## 1. 方針

「機能量」より「安全に使える小規模Pilot」を優先し、Monitor → Development → Verify → Improvementの順で段階的に進める。日程、担当者、予算は**未決**である。

## 2. 段階計画

| 段階 | 主な作業 | 完了条件 |
|---|---|---|
| 0. 判断確定 | 未決事項、責任者、バックアップ、RPO/RTO、データ移行対象を決定 | 重要な未決事項が承認済み |
| 1. 基盤構築 | Linux、コンテナ、10TB HDD、ext4、UUIDマウント、権限、監視 | 再起動後も`/mnt/storage`が安全に利用可能 |
| 2. 中核実装 | 認証、Workspace、Project、Files、Chat、Work、Agent、Audit、Quota | 機能・権限テストが合格 |
| 3. 条件付き移行 | 既存4TBに対象データがある場合のみコピー・照合 | 件数、総量、チェックサム、受入確認が合格 |
| 4. Pilot準備 | 約10名、教育、運用手順、バックアップ、復元試験 | Pilot開始判定が承認済み |
| 5. Pilot | 3～6か月を目安に利用量、効果、障害、性能を測定 | KPIと課題が報告済み |
| 6. 正式化判断 | 容量拡張、冗長化、SSO等の要否を評価 | 継続、改善、停止の判断が記録済み |

## 3. 優先順位

1. セキュリティ、データ損失防止、バックアップ・復元
2. 未マウント誤書込み防止、監視、Quota
3. Pilotに必要な中核業務フロー
4. 性能・運用改善
5. 将来連携と追加機能

## 4. 将来候補

Entra ID SSO、OneDrive、SharePoint、GitHub、MCP、他LLM Provider、冗長ストレージ、全社展開は将来候補であり、採用は**未決**である。Pilot実績、セキュリティ、費用、運用負荷を確認して個別に判断する。

## 5. ゲート

各段階でlint、test、build、セキュリティ、バックアップ復元、文書整合性を確認する。未検証の変更を完了・リリース扱いにしない。

# セキュリティ設計

**文書状態：設計段階**  
**対象：Mirai AI ワークプラットフォーム Pilot**

## 1. 目的と保護対象

本書は、利用者データ、Projectデータ、成果物、会話、Knowledge、認証情報、DeepSeek API Key、監査ログ、設定、ソースコードを保護するための設計基準を定める。

## 2. 想定脅威

| 領域 | 主な脅威 | 基本対策 |
|---|---|---|
| Web/API | 認証回避、IDOR、CSRF、XSS、インジェクション | サーバー側認可、入力検証、出力エスケープ、CSRF対策、パラメータ化 |
| Files | Path Traversal、symlink escape、危険ファイル、Quota回避 | 相対パス限定、正規化後検証、MIME/容量制限、保存名分離、チェックサム |
| Agent | Prompt Injection、過剰Tool権限、ホスト侵害、資源枯渇 | 一時Sandbox、権限Profile、対象Workspace限定、CPU/Memory/時間/出力上限 |
| LLM連携 | 秘密情報送信、Tool結果の盲信、外部API障害 | 送信データ最小化、秘密検知、Tool結果検証、タイムアウト、利用量記録 |
| Storage | 単一HDD故障、未mount時の誤書込み、容量枯渇 | 状態検証、fail-closed、容量保護、別系統バックアップ、復元試験 |
| Supply Chain | 依存関係脆弱性、改ざん成果物 | lockfile、脆弱性検査、固定版、レビュー、CIゲート、出所確認 |

## 3. 境界防御

- 外部通信は原則HTTPSとし、TLS証明書検証を無効化しない。
- API GatewayでRequest ID、認証、レート制限、サイズ制限を適用する。
- DB、管理ポート、Container Runtimeを利用者ネットワークへ直接公開しない。
- CORSは必要なOriginだけを明示し、資格情報付きワイルドカードを禁止する。
- セキュリティヘッダーはCSP、frame制御、MIME sniffing防止等を構成に応じ設定する。

## 4. ファイルとストレージ

ファイルの保存先はDB上の所有者情報とサーバー側のパスマッピングから決定する。利用者が絶対パスを指定する設計は禁止する。展開処理ではZip Slip、展開後容量、ファイル数、入れ子深度を制限する。

新規10TB外付けHDDはext4で構成し、UUID指定で `/mnt/storage` に直接マウントする。起動時と書込み前に、mountpoint、期待UUID、read-write状態、空き容量を検証する。未マウント、read-only、I/OエラーではUpload、Artifact生成、更新処理を停止し、ルートファイルシステムへフォールバックしない。

単一HDDはバックアップでも冗長化でもない。重要データ、DB、設定、監査情報は別媒体または別システムへ暗号化して保存し、復元できることを試験する。

## 5. Agent Sandbox

- 実行ごとに破棄可能な一時Containerを使用する。
- root実行を避け、Linux capability、device、privileged modeを必要最小限とする。
- `/mnt/storage` 全体ではなく対象Workspaceだけをbind mountする。
- Network、Shell、File Toolは業務Profileごとに明示許可する。
- ホストSocket、Secret格納先、他ユーザー領域を公開しない。
- Tool入力と出力を検証し、破壊的・外部送信操作には追加承認を設ける。

## 6. Secret管理

- API Key、DB資格情報、Cookie署名鍵をソース、HTML、ログ、DB本文へ平文保存しない。
- 実行環境のSecret機構または権限制限されたSecretファイルを用いる。
- 開発、検証、本番相当環境でSecretを分離する。
- 漏えい時の無効化・再発行手順と所有者を定める。
- ログ、例外、Agent PromptへSecretが出力されないようマスキングする。

## 7. セキュア開発ゲート

変更はレビュー、lint、unit test、integration test、build、依存関係検査、秘密情報検査を通過させる。重大・高リスクの未解決事項がある状態でリリースしない。検査ツールの未実行と「問題なし」を区別し、証跡を保存する。

## 8. インシデント対応

不正アクセス、Secret漏えい、マルウェア疑い、データ破損を検知した場合は、証拠保全、影響範囲特定、資格情報失効、隔離、復旧、再発防止の順で対応する。ログ削除や疑わしいHDDへの書込みを先に行わない。

## 9. Pilot開始前の確認

- 脅威モデルとデータ分類を承認する。
- Role別の拒否テスト、Path Traversal、symlink、Quota境界を試験する。
- AgentのContainer脱出・越境を防ぐ設定をレビューする。
- 10TB HDD未マウント時のfail-closedを実機確認する。
- 別系統バックアップの復元試験を行う。
- 本番相当Secretがリポジトリや成果物に含まれないことを確認する。

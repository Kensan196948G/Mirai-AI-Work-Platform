Mirai AI ワークプラットフォーム 要件定義書

英語名：Mirai AI Work Platform
Repository：Mirai-AI-Work-Platform

1. システム目的

社内ユーザーがWebブラウザからAIチャット、AI業務実行、プロジェクト作業、ファイル処理、成果物生成を安全に利用できる共通基盤を提供する。

2. 利用者要件

利用者要件
Pilot User初期約10名。個人Workspace、Project、Chat、Work、Filesを利用可能。
Project OwnerProject作成、メンバー追加、Quota管理、Project設定変更。
IT/DX Adminユーザー、Project、ストレージ、AI設定、監査ログ、システム状態を管理。

3. 機能要件

3.1 Chat

  • DeepSeek APIとの対話
  • 会話履歴保存
  • Projectコンテキストの選択
  • ファイル添付

3.2 Work

  • Goal入力
  • Plan生成
  • Tool実行
  • Task進捗表示
  • Artifact生成
  • Review/再実行

3.3 Projects

  • Project作成・編集・削除
  • Projectメンバー管理
  • ProjectごとのWorkspace、Files、Knowledge、Artifacts
  • Project単位Quota

3.4 Files

  • アップロード、ダウンロード、削除、移動、一覧表示
  • Office、PDF、テキスト、画像等を対象
  • ファイルメタデータ管理
  • サイズ、所有者、Project、作成日時、更新日時を記録

3.5 Agents

  • DeepSeekを中心としたAgent実行
  • Sandbox内でのFile/Shell等Tool利用
  • 他ユーザー・他Project領域をマウントしない
  • 実行履歴、開始/終了、状態、エラーを保存

3.6 Artifacts

  • HTML、Markdown、PDF、Office文書等の成果物保存
  • Project/Userとの紐付け
  • 生成履歴管理

3.7 Storage

  • 新規10TB外付けHDD 1台をext4で構成し、Linuxの/mnt/storageへ直接マウントする
  • 既存4TB HDDおよび新規4TB HDDを組み合わせる構成とmergerfsは採用しない
  • アプリケーション側Quotaを実装する
  • 使用率、マウント状態、I/Oエラー、取得可能な場合はS.M.A.R.T.情報を監視し、警告を管理画面へ表示する
  • 将来の容量拡張は、Pilotの実測値に基づいて移行方式または冗長構成を別途設計する

3.8 Admin

  • ユーザー管理
  • Role管理
  • Quota変更
  • Project管理
  • ストレージ使用量可視化
  • Agent実行状況確認
  • 監査ログ検索

4. 非機能要件

項目要件
可用性Pilot中の業務利用に耐えること。単一HDD障害、切断、未マウントを検知し、誤った保存先への書込みを防止する。障害時の復旧手順を文書化する。
性能10名Pilotで通常利用に支障のない応答性。同時Agent実行数は構成に応じ制限可能。
拡張性ユーザー、Project、LLM Providerを段階追加可能とする。ストレージ拡張は10TBの使用実績に基づき、データ移行または冗長構成を再設計する。
セキュリティ最小権限、Sandbox、Path Traversal対策、ファイル種別/容量制限、秘密情報を環境変数/Secret管理。
監査ログイン、File操作、Agent実行、管理操作、設定変更を記録。
保守性Docker/Container化、設定外部化、ログ一元化、GitHubでソース管理。

5. ストレージ要件

項目要件
物理構成新規10TB外付けHDD 1台。既存4TB HDDは初期運用ストレージへ統合しない。
ファイルシステムext4
マウントHDDのUUIDを使用して/mnt/storageへ直接マウントする。アプリケーション起動前にマウント済みであることを検証する。
容量メーカー公称10TB（約9.1TiB）。実使用可能容量はフォーマットと予約領域によりさらに小さくなるため、構築後の実測値を管理基準とする。
User QuotaPilot初期候補100GB/User。実使用量を計測し見直す。
Project Quota50/100/500GB等の可変設定。User Quotaとの集計・優先関係を実装時に一意に定義する。
運用予備ファイルシステム全体の10%以上を運用予備として確保し、User/Project Quotaの合計値にかかわらずストレージ全体の保護制限を優先する。
拡張使用率80%到達前に、より大容量の媒体への移行、追加ストレージ、または冗長構成を選定する。mergerfsによる自動追加は初期スコープ外とする。
警告70%注意、80%拡張計画開始、85%管理者警告、90%大容量処理制限、95%緊急保護
バックアップ重要データを10TB HDDとは別の媒体または別システムへ定期保存し、復元確認を行う。

6. データ保持要件

  • Project/User本体データは明示削除まで保持。
  • Tempは24時間〜7日で自動削除可能。
  • Processingデータは処理完了後に削除。
  • 監査ログはPilot中は原則保持し、正式運用時に保持期間を確定。
  • バックアップの対象、頻度、保持世代、暗号化、復元目標はPilot開始前に運用手順として確定する。

7. 外部連携要件

  • DeepSeek API
  • GitHub（将来/段階導入）
  • MCP（将来）
  • SSO、OneDrive、SharePointは現時点でスコープ外・保留

8. 受入条件

  • 10名が独立Workspaceを利用できる。
  • Project共有領域が利用できる。
  • Agentが他領域へアクセスできない。
  • Quota超過を防止できる。
  • 新規10TB HDDがUUIDにより/mnt/storageへ正しくマウントされ、再起動後も同一パスで利用できる。
  • HDD未接続または未マウント時にアプリケーションが書込み処理を開始しない。
  • 使用率の警告・制限とストレージ障害通知を確認できる。
  • 重要データを別媒体または別システムのバックアップから復元できる。
  • 管理者が利用量・エラー・監査ログを確認できる。
